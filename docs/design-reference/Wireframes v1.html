design notes — what we're optimizing for
Promise: "tells students what to do today, when to do it, and never writes to their calendar without permission."
Daily-driver test: home view = today's blocks + 1 agent prompt + Done buttons. nothing else competing.
Trust visuals: proposed = dashed/yellow. accepted = solid. done = struck-through. clear visual grammar.
Agent stays in a box: LLM proposes, deterministic dispose. UI should reinforce this — labelled "draft", "preview", "approve".

trust visuals · the brand promise
consistent across every screen. these are non-negotiable.
1. the dashed-yellow rule
if it's dashed-yellow, it isn't on your calendar yet. ever. no exceptions.
2. one approval gate per session
the agent never writes silently. one explicit "approve" per batch. always reversible for 60s.
3. "why this?" on every block
tap any block, see prereqs + milestone. demystifies the agent.
4. sponsor visibility = opt-in fields
share % done + milestones, not raw blocks. user previews every report.
5. drift > punishment
behind = "let's recover", never "you failed". no streaks-as-shame, no gamified guilt.
